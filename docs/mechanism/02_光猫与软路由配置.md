# 光猫与软路由配置

> 讲清楚: 电信光猫如何配置(桥接模式)、两种IPTV接入方式(网口绑定 vs VLAN)的优缺点、
> OpenWRT如何配置及工作原理、注意事项。
>
> ⚠️ IP/域名已脱敏,真实值见 .env

---

## 一、整体架构

```
电信PON光纤
    │
[光猫 HS8125C] ── 桥接模式(二层透传 + IGMP Proxy) ──────
    │  职责: 1)透传电信多个VLAN给软路由  2)组播IGMP代理  3)不做NAT/路由
    │
    │  电信侧VLAN划分:
    │    VLAN 41 → INTERNET(上网,PPPoE)
    │    VLAN 43 → IPTV(组播VLAN 4000)
    │    VLAN 46 → VOICE(电话)
    │
    ├──[方式A:网口绑定] 光猫LAN2口(绑定VLAN43) → 软路由独立网口
    └──[方式B:VLAN透传] 光猫某口(透传WAN+VLAN43) → 软路由一个口打tag
    │
[软路由 OpenWRT] ── PPPoE拨号 + NAT + 防火墙 + 路由 + IPTV接入
    ├── LAN → 家庭设备
    └── IPTV接口 → msd_lite(组播转HTTP) + RTSP路由
```

**核心**: 光猫桥接模式,只当"二层管道+组播代理",所有智能在软路由。
光猫的IGMP Proxy **不能关**(关了所有组播频道不通)。

---

## 二、两种IPTV接入方式对比 ⭐

这是本文重点。光猫把IPTV(VLAN43)送给软路由有两种接线方式:

### 方式A: 网口绑定(独立物理口)
```
光猫LAN2口(在光猫后台绑定到VLAN43) ──网线──> 软路由独立网口(如USB网卡)
```
- 光猫后台: 把某个LAN口(如LAN2)划给IPTV(VLAN43,untag输出)
- 软路由: 该网口直接是IPTV接口,收到的就是untag的IPTV流量

### 方式B: VLAN透传(与WAN共线)
```
光猫某口(透传 WAN untag + IPTV VLAN43 tag) ──一根网线──> 软路由一个口
                                                          ├─ untag → PPPoE上网
                                                          └─ VLAN43 tag → eth1.43 → IPTV
```
- 光猫后台: 某口配成透传,同时送上网(untag)和IPTV(打VLAN43 tag)
- 软路由: 该口建VLAN子接口(如eth1.43)分离IPTV流量

### 优缺点对比

| 维度 | 方式A(网口绑定) | 方式B(VLAN透传) |
|------|----------------|-----------------|
| 网线数 | 2根(WAN + IPTV各一) | **1根**(共线) |
| 软路由网口 | 需2个物理口(或USB网卡) | 1个物理口即可 |
| 带宽 | IPTV独占该口带宽 | 与WAN共享(但千兆口余量足) |
| 隔离性 | 物理隔离,互不影响 | 逻辑隔离(VLAN tag),千兆下也不打架 |
| 配置复杂度 | 简单(光猫绑口即可) | 需光猫透传+软路由建VLAN子接口 |
| 受限场景 | 需额外网口;USB网卡有瓶颈 | 光猫该口需支持透传 |
| 光猫口速率坑 | 若绑的口是百兆,IPTV限百兆 | 同左,取决于光猫口 |

### 本项目的选择与教训
- **曾用方式A**: USB千兆网卡(AX88179)当IPTV口。但软路由(J1900)只有USB2.0,
  实测上限~89Mbps(单流42M),4K@50fps(32M)紧张。**USB网卡是瓶颈**。
- **后改方式B**: 板载千兆口eth1透传WAN+VLAN43。摆脱USB瓶颈,一根线搞定。
- **注意**: 若光猫的IPTV口物理上是百兆(如HS8125C),方式B也受限百兆。
  但百兆(实测89M)跑单路4K够用,瓶颈更多在播放器缓冲(见FAQ)。

**建议**: 有富余千兆口 + 光猫支持透传 → **方式B**(省线省口,摆脱USB)。
否则方式A也可,但避免用USB2.0网卡跑高码率。

## 三、OpenWRT 配置

### 3.1 IPTV接口(方式B: VLAN子接口示例)
```
# VLAN 43 子接口设备
config device
    option type '8021q'
    option ifname 'eth1'
    option vid '43'
    option name 'eth1.43'

# IPTV接口
config interface 'zIPTV'
    option proto 'dhcp'
    option device 'eth1.43'          # 方式A则填独立网口如eth2
    option macaddr '<STB_MAC>'        # 克隆机顶盒MAC(IPoE认证关键!)
    option hostname '<STBID>'         # DHCP Option12
    option sendopts '0x3c:<hex>'      # DHCP Option60(IPoE认证)
    option delegate '0'
    option multipath 'off'            # 关闭!否则双DHCP冲突
    option metric '200'
    option defaultroute '0'           # 禁止DHCP默认路由(避免和PPPoE冲突)
    option peerdns '0'                # 禁止用IPTV的DNS
```

### 3.2 防火墙(让LAN设备能访问IPTV)
```
# IPTV zone 开启 masquerading(NAT伪装)
config zone
    option name 'IPTV'
    option network 'zIPTV'
    option masq '1'          # ← 必须!否则EPG服务器看到LAN内网IP,认证失败
    option mtu_fix '1'

# lan → IPTV 转发(方向必须是lan→IPTV)
config forwarding
    option src 'lan'
    option dest 'IPTV'
```

### 3.3 RTSP路由(单播频道命脉)
EPG/RTSP服务器在IPTV专网,LAN设备默认走PPPoE到不了,需加路由:
```
115.233.40.0/21   → IPTV网关   # EPG+RTSP入口+流媒体
220.191.136.0/24  → IPTV网关   # EDS认证+RTSP重定向
122.229.6.0/24    → IPTV网关   # 4K流媒体终点
```
用 hotplug 脚本动态添加(适配DHCP动态IP + 动态设备名):
```sh
# /etc/hotplug.d/iface/99-iptv-routes
[ "$ACTION" = "ifup" ] || exit 0
[ "$INTERFACE" = "zIPTV" ] || exit 0
sleep 3
DEV=$(ubus call network.interface.zIPTV status | jsonfilter -e '@.l3_device')
GATEWAY=$(ubus call network.interface.zIPTV status | jsonfilter -e '@.inactive.route[0].nexthop')
[ -z "$GATEWAY" ] && GATEWAY=$(ubus call network.interface.zIPTV status | jsonfilter -e '@.data.dhcpserver')
for net in 115.233.40.0/21 220.191.136.0/24 122.229.6.0/24; do
    ip route del $net 2>/dev/null
    ip route replace $net via "$GATEWAY" dev "$DEV"
done
```

### 3.4 注意事项(踩过的坑)
| 坑 | 说明 |
|----|------|
| multipath导致双DHCP | zIPTV必须 `multipath 'off'`,否则udhcpc冲突 |
| 路由写死dev | hotplug脚本 `dev` 要动态获取(切VLAN后设备名变),写死会导致单播路由失效→4K不能播 |
| ip route del不带dev | 删竞争路由时不带dev(才能删掉pppoe-wan的) |
| masq必须开 | 否则EPG认证失败(源IP是LAN内网) |
| DHCP动态IP | IP变→网关变,用hotplug动态适配,别写静态路由 |

### 3.5 工作原理小结
```
LAN设备看组播: 设备 → msd_lite(软路由) → IGMP join → IPTV接口 → 光猫Proxy → 组播源
LAN设备看单播: 设备 → RTSP → (走RTSP路由)IPTV接口 → RTSP服务器 → UDP单播流
认证: 软路由克隆机顶盒MAC + Option60,DHCP时IPoE认证通过,拿IPTV网段IP
```
