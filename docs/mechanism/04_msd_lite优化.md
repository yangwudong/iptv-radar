# msd_lite 配置优化 & 与 udpxy 对比

> 讲清楚: 组播转HTTP工具msd_lite的作用、配置优化、以及和udpxy的对比分析。
> msd_lite 把 UDP 组播流转成 HTTP 单播,让不能直接收组播的设备(手机/电视/VLC)也能播。

---

## 一、为什么需要组播转HTTP

组播(IGMP+UDP)有天然限制:
- 很多客户端(iOS/浏览器/部分播放器)**不支持直接收UDP组播**
- 组播只在特定网段可达,跨网段/WiFi常收不到

**msd_lite/udpxy 的作用**: 在软路由上收组播,转成HTTP流,客户端用普通URL播放:
```
组播: rtp://233.50.201.118:5140  (需组播环境,兼容性差)
  ↓ msd_lite转换
HTTP: http://<软路由>:4088/rtp/233.50.201.118:5140  (任何设备可播)
```

---

## 二、msd_lite vs udpxy 对比 ⭐

两者都是组播转HTTP工具,udpxy更老更知名,msd_lite更新更高性能。

| 维度 | msd_lite | udpxy |
|------|----------|-------|
| 架构 | 多线程+线程池,事件驱动(epoll/kqueue) | 每客户端fork进程(经典)/单线程 |
| 零拷贝 | ✅ sendfile(),内核直发,低CPU | 一般用户态拷贝 |
| 并发模型 | 无锁消息传递,每线程独立hub | 进程/线程较重 |
| **多客户端共享同一流** | ✅ 一个组播流一个hub+共享环形缓冲,多客户端各自读位置 | 每客户端各自join组播(重复流量) |
| 资源占用 | 环形缓冲延迟分配(首个客户端才建),内存映射 | 每连接独立开销 |
| 慢客户端处理 | ✅ 可配置断开落后太多的慢客户端 | 较弱 |
| 配置 | XML配置文件,可精细调线程/缓冲/TCP选项 | 命令行参数,简单 |
| CPU绑定 | ✅ 线程可绑核,优化缓存 | - |
| 成熟度/知名度 | 较新,OpenWRT可装 | 老牌,应用广 |

### 关键差异: 多客户端共享
- **msd_lite**: 3个设备看同一个CCTV1 → 软路由只**join一次**组播,一个环形缓冲,3个客户端共享读。上游带宽 = 1路。
- **udpxy**: 3个设备看CCTV1 → 可能各自处理,上游带宽压力更大。

### 结论/选型
- **家用多设备 + 追求性能/低CPU** → **msd_lite**(本项目选择)
- **简单场景 + 要成熟稳定** → udpxy 也够用
- 本项目软路由是弱鸡J1900,msd_lite的零拷贝+低CPU很关键

## 三、msd_lite 配置优化

### 3.1 OpenWRT 安装
```bash
opkg update && opkg install msd-lite   # 或从源码编译
```

### 3.2 关键配置(msd_lite.conf / OpenWRT uci)
```
# HTTP服务端口(udpxy兼容接口)
bind: 0.0.0.0:4088

# 线程池: 按CPU核数(J1900是4核)
threads: 4
threadsBindToCPU: true          # 绑核,优化缓存

# 环形缓冲(每个组播流): 影响卡顿和延迟
ringBufSize: 4M                 # 高码率4K流建议加大(默认可能偏小)

# TCP优化
tcpNoDelay: true                # 降延迟
tcpNoPush: true                 # (Linux TCP_CORK)提吞吐

# 慢客户端: 落后太多就断开,防拖累
dropSlowClients: true
```

### 3.3 针对4K高码率优化
4K@50fps ~32Mbps,默认缓冲可能不够,导致卡顿:
- **加大 ringBufSize**(如4M→8M),给高码率流更多缓冲空间
- 确保软路由IPTV口带宽够(见 02_光猫与软路由配置.md 的方式A/B权衡)

### 3.4 访问格式(udpxy兼容)
```
http://<软路由IP>:4088/rtp/233.50.201.118:5140    # rtp/组播地址
http://<软路由IP>:4088/udp/233.50.201.118:5140    # udp/(等价)
```
本项目脚本用 `/rtp/` 格式。

## 四、验证与调试

```bash
# 测试拉流(应有h264/hevc流)
ffprobe http://<软路由IP>:4088/rtp/233.50.201.118:5140

# 看msd_lite状态/统计(部分版本有web状态页)
curl http://<软路由IP>:4088/

# 多客户端测试: 同时几个设备播同一频道,看软路由上游是否只有1路组播流
```

### 常见问题
| 问题 | 原因/解决 |
|------|----------|
| 拉流卡顿 | 加大ringBufSize;检查IPTV口带宽 |
| 拉不到流 | 检查组播是否可达(光猫IGMP Proxy);该频道本区域是否推送 |
| 4K花屏 | 缓冲不足;或本区域无此组播(202.x)需走RTSP单播 |
| PPS警告(ffprobe) | 组播从中间接入正常现象,不影响 |
