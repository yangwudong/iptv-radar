# 浙江电信IPTV 233.50.202.x频道无法播放 — 根因分析报告

> 分析日期: 2026-06-21
> 环境: 杭州电信宽带+IPTV / OpenWRT 25.12 / msd_lite / HS8125C光猫(桥接模式)

---

## 一、问题描述

在OpenWRT软路由上通过msd_lite将IPTV组播转单播播放时:
- **233.50.200.x / 233.50.201.x 频道**: 正常播放 ✅
- **233.50.202.x 频道**: 无法播放 ❌ (包括4K频道和普通高清频道)

将电信原装机顶盒(华为EC6108V9U)接到同一个光猫网口上,202.x频道(含4K)可以正常观看。

---

## 二、排除项(不是问题的原因)

| 排查项 | 结论 | 依据 |
|--------|------|------|
| IGMP v2 vs v3 | **排除** | GitHub上能看202.x的大佬抓包确认用的也是IGMPv2 |
| ISP封锁202.x | **排除** | 机顶盒在同一个光猫口上能正常播放202.x |
| 光猫配置错误 | **排除** | IGMP Snooping/Proxy正常,组播VLAN 4000配置正确 |
| 编解码问题 | **排除** | 202.x包含4K(HDR HEVC)和普通高清(H264),均无法播放 |
| DHCP/IPoE认证 | **排除** | OpenWRT已配置Option 60+MAC克隆,认证通过 |
| 端口绑定 | **排除** | OpenWRT的eth2和机顶盒都接在光猫网口2(LAN2) |
| 光猫IGMP Proxy | **必要但非根因** | 关闭后所有频道都不通;开启后200/201正常,202仍不通 |

---

## 三、根因

### **233.50.202.x频道在本区域不通过组播分发,机顶盒通过EPG中间件获取单播UDP流观看。**

机顶盒和OpenWRT使用完全不同的方式访问202.x频道:

```
机顶盒看202.x的方式(能看):
  1. DHCP认证 → 获取IPTV IP
  2. HTTP认证到EPG服务器(115.233.40.140:33200)
  3. 获取频道列表和单播流地址
  4. 从115.233.45.x服务器接收UDP单播视频流 ✅

OpenWRT看202.x的方式(看不了):
  1. DHCP认证 → 获取IPTV IP
  2. msd_lite发送IGMP join到 233.50.202.x(组播地址)
  3. 上游BRAS根本没有推送这路组播流 → 无视频流返回 ❌
```

### 关键区别

| 对比项 | 200.x/201.x频道 | 202.x频道 |
|--------|----------------|-----------|
| 分发方式 | **组播**(Multicast) | **单播**(Unicast) |
| 协议 | IGMP join + UDP组播 | EPG中间件 + UDP单播 |
| 组播地址 | 233.50.200.x / 201.x | 233.50.202.x (仅EPG引用,实际不用) |
| 视频源 | 122.229.7.118(组播源) | 115.233.45.153/154/132(单播服务器) |
| OpenWRT能看? | ✅ | ❌ |
| 机顶盒能看? | ✅ | ✅ |

## 八、已排除的其他排查路径

### 8.1 强制IGMPv3

- OpenWRT内核 `force_igmp_version=3` 不生效(GitHub #15219已知问题)
- nftables丢弃光猫v2 query → 内核仍发v2 report
- 结论: **不是IGMP版本问题**(大佬用v2也能看)

### 8.2 RTSP单播

- RTSP服务器 `115.233.41.137` ping通(从IPTV网络,3ms)
- TCP port 554 连接超时(防火墙静默丢弃)
- ffmpeg拉流失败
- 结论: **本区域RTSP端口554被封**

### 8.3 关闭光猫IGMP Snooping/Proxy

- 关闭后所有频道(含200.x/201.x)全部不通
- 光猫不是纯透明桥,IGMP Proxy是组播转发的必要条件
- 结论: **Proxy必须开启,但Proxy不是202.x不通的原因**

### 8.4 macOS直连测试

- Mac克隆MAC+静态IP直连光猫,VLC无法播放任何频道
- 原因: Mac未配置DHCP Option 60,BRAS不认证
- 结论: **DHCP认证是必要条件,但不是充分条件**

## 九、可行的解决方案

### 方案A: 接受现状(最简单)

- 200.x/201.x频道: 继续用OpenWRT + msd_lite组播
- 202.x频道(4K卫视等): 用机顶盒观看
- 优点: 零配置
- 缺点: 无法在所有设备上观看202.x频道

### 方案B: 模拟EPG认证获取单播流(最完整但最复杂)

需要编写脚本模拟机顶盒的EPG认证流程:
1. DHCP认证(已有配置)
2. HTTP认证到 `115.233.40.140:33200`
3. 获取频道列表(解析JSON/HTML响应中的流地址)
4. ffmpeg拉取UDP单播流并转为HTTP
5. 优点: 全自动化,所有设备可看
6. 缺点: 开发复杂, UserID/认证可能过期

### 方案C: 打10000号要求开通组播

- 向电信报修,要求在所在区域的BRAS上开通202.x组播
- 优点: 根治问题
- 缺点: 客服可能不理解组播概念,需要反复沟通

### 方案D: 使用其他区域的RTSP源

- 博客作者(luckyyyyy)所在区域RTSP(554端口)可用
- 但用户所在区域554端口被封
- 如果能找到RTSP的替代端口或其他服务器IP,可能有转机
